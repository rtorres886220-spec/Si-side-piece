The problem

Most browser agents are a chat window with unchecked hands.

They answer fluently, click confidently, and fail quietly — with no guarantee a quote is real, a number wasn't invented, or a payment field stayed untouched.

Typical agent

Trusts the model

The LLM picks the element, writes the answer, and judges its own work. Hallucinated numbers and phantom targets pass straight through.

Sidekick

Trusts the invariants

The model proposes. A deterministic gate verifies quotes verbatim, checks numbers against source, confirms the target exists, and blocks sensitive fields — before anything executes.

Architecture

A pipeline where the cheapest correct stage wins.

Every request is routed to the lightest path that can solve it. Regex before router, router before model, and a hard gate before any output leaves.

Capabilities

Built to act on the real web, not a simulation of it.

Just-in-time CDP automation

When a task needs trusted input, Sidekick attaches the Chrome debugger on demand and dispatches real pointer sequences — so pages that ignore synthetic clicks still respond. It detaches when done, and falls back to a synthetic pointer sequence when DevTools already holds the tab.

// resolve → verify → act target = resolve("[#42] Start survey") gate.check(target) // exists? bounded? not a payment field? cdp.click(target) // trusted pointer events

Click-to-locate citations

Answers carry verbatim quotes. Click a citation and the page scrolls to and highlights the exact source text.

Survey & form engine

A question-by-question state machine with explicit stages and a bounded autonomy policy.

  • Observe → parse → resolve → validate → execute → verify → advance
  • Pauses on personal-info and ambiguous questions rather than inventing answers
  • Cycle and thrashing detection
  • Consequential submits require authorization

Multi-tab & tab-group aware

Scope a task to the active tab or a whole tab group. Sidekick keeps track of what it sees across tabs and resolves ambiguous scope before acting.

  • Tab-group scoping
  • Per-tab content-script liveness
  • Protected-page detection (chrome://, Web Store)

Token-aware by design

Retrieval returns relevant sections within a budget, and zero-LLM shortcuts handle simple commands.

Reality-mediated evaluation DESIGN SPEC

The same CDP harness is specified as a hypervisor that can interrogate other agents: inject hostile DOM, lookalike CTAs and dynamic traps, then judge which actions survive deterministic constraints. Documented in the repo's architecture reports.

Self-diagnosis

When it breaks, it tells you why.

A built-in Doctor audits the extension from inside the extension — no server, no guessing — and offers one-click fixes.

  • API key check — pings Gemini directly and validates key format.
  • Tab eligibility — flags pages Chrome forbids extensions from touching.
  • Content-script liveness — auto-injects into tabs opened before install.
  • CDP controller — detects an open DevTools lock and selects the fallback.
Trust & safety

Hard limits that don't depend on the model behaving.

Zero-trust target resolution

Every action must resolve to an element that exists in the current DOM. Phantom targets are rejected before execution.

Sensitive-field lockout

Card numbers, CVV, passwords, SSN and similar inputs are blocked by pattern, regardless of what the model asks for.

Verbatim grounding

Quoted evidence is normalised and matched against the source page. Numbers in answers are checked against numbers in the evidence.

Your key, your browser

You bring your own Gemini API key from Google AI Studio. The extension's content security policy limits network calls to the Gemini endpoint and local development hosts.

Declared Chrome permissions

Full transparency on what the manifest requests — no hidden surface.
